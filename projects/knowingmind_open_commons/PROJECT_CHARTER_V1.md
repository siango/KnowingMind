# KnowingMind Open Commons — Project Charter V1

## Purpose

Create an open public commons around KnowingMind / เอไอตัวรู้ so developers, translators, researchers, donors, reviewers, educators, practitioners, and ordinary users can contribute to a sustainable knowledge system.

The project is not a conversion funnel. Its purpose is to make knowledge inspectable, traceable, multilingual, and practically useful while preserving the user's freedom to accept, reject, compare, or suspend judgment.

## Scope

In scope:

- open-source application code that passes public classification,
- public schemas and API contracts,
- public UI and documentation,
- synthetic fixtures and tests,
- multilingual content infrastructure,
- contribution and review workflows,
- membership and recognition,
- funding transparency,
- public sustainability reporting,
- interfaith and non-religious knowledge-domain support,
- provenance and evidence presentation.

Out of scope unless separately approved:

- production secrets,
- credentials and tokens,
- private user/practice records,
- raw copyrighted PDFs without redistribution rights,
- private evidence,
- internal production endpoints,
- authentication secrets,
- payment credentials,
- infrastructure that is shared but not classified for public release.

## Knowledge posture

KnowingMind must distinguish at least:

SOURCE → TRADITION/DOMAIN → EVIDENCE → INTERPRETATION → AI ANALYSIS

The system must not collapse distinct religious traditions into a single asserted truth. It must not rank religions or coerce users toward Buddhism.

DHAMMA_GROUNDED_AI remains a specific verified Dhamma domain with its own Canon provenance and authority boundaries.

## Human-agency commitment

Users should be able to:

- inspect where a claim came from,
- see when a statement is interpretation rather than source text,
- compare perspectives,
- ask for counterevidence or conflict,
- use the system without adopting any religion,
- choose language and knowledge domain,
- understand when AI is uncertain.

## Financial independence rule

Donations and sponsorship may support infrastructure and development. They must not buy:

- Canon authority,
- doctrinal truth status,
- source-verification outcomes,
- reviewer override,
- user-attainment certification,
- undisclosed product influence.

## Completion definition

The subproject is complete only when public-alpha release gates pass, not merely when documents or source files exist.
